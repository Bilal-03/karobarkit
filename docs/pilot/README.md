# KarobarKit freelancer pilot

Status: setup implemented; customer discovery, adoption and commercial demand are unvalidated. No interviews or pilot outcomes have been fabricated. The public workflow is a hypothesis, not validated positioning.

Start here: [research kit](research.md), [measurement](measurement.md), [decision log and PRD](decisions.md), [growth experiments](growth.md), [portfolio](portfolio.md), and [SQL exercises](analysis.sql).

## Six-week operating plan

| Week | Owner action                                                     | Evidence required before moving on                           |
| ---- | ---------------------------------------------------------------- | ------------------------------------------------------------ |
| 1    | Interview 5–8 Indian freelancers about recent paperwork          | Observation log; current workaround; frequency; consent      |
| 2    | Rank repeated, consequential problems and measure baseline tasks | One problem brief, funnel definitions, observed counts       |
| 3    | Retest quotation → invoice continuity as the default hypothesis  | Short PRD, changed behavior, observed task results           |
| 4    | Recruit approximately 10–15 participants through two channels    | Invitations, effort, spending, source and activated counts   |
| 5    | Follow up on real document use and recurring tasks               | Failure synthesis and one evidence-backed revision           |
| 6    | Publish a case study and record a three-minute demo              | Verified evidence, limitations, resume bullet, next decision |

Numbers are recruitment targets, not achieved results. Keep a weekly decision review: evidence → interpretation → decision → owner → revisit date. If recruitment fails, change the recruitment approach and record it. Do not count your own browser tests as customers.

Use [the pilot workbook](../../outputs/karobarkit-pilot/pilot-workbook.xlsx) for manual task observations and weekly channel results. It is an empty template. Store consent/contact details separately from pseudonymous research records; do not commit real participant records or analytics exports to GitHub. Repeat-use research is opt-in and manual; anonymous sessions cannot identify returning people.

## Readiness gates

Before recruiting: verify live Vercel custom-event ingestion; run quotation → invoice → receipt with dummy data; check mobile export; confirm full tax breakdown. Before publishing claims: verify denominators, distinguish test traffic, reconcile counts and obtain permission for any quoted feedback. Review costs weekly, separating hosting and AI. Stop discretionary spend if an agreed budget would be exceeded; no automatic upgrades are part of this implementation.
